# Final Review – Responsible Use of the Edge Weather Station

## 1. What I Built

I developed a Raspberry Pi 4 weather station using a Sense HAT to collect temperature, humidity and pressure readings.

The system stores observations locally in SQLite, calculates environmental states using a five-reading window and runs a small Ridge Regression model to predict temperature approximately 60 seconds ahead.

I also implemented MQTT communication with a Windows PC, an LED status display and a local Flask dashboard.

## 2. Evidence from Testing

The project collected 972 real Sense HAT observations for model training.

On the held-out test set, Ridge Regression achieved a mean absolute error of 0.0900°C, compared with 0.1012°C for the persistence baseline.

The model was successfully deployed on the Raspberry Pi and produced forecasts from live sensor measurements.

Three independent benchmarks showed median inference times between 0.014500 and 0.014778 milliseconds.

All 25 unit tests passed, including checks for invalid data, incompatible model inputs, stale readings and unauthorised web requests.

I also tested the physical LED display, dashboard updates, keyboard navigation, zoom and narrow-screen layout.

## 3. Privacy and Security

The system uses the neutral station identifier `station01` and does not intentionally collect personal identifiers.

However, timestamps and environmental patterns could potentially reveal information about room activity.

The classroom MQTT configuration used anonymous, unencrypted communication. This would not be suitable for a production deployment.

After testing, I cleared the retained MQTT telemetry and status messages and disabled Mosquitto.

Other copies, including SQLite databases, CSV exports and training files, remain subject to separate retention decisions.

## 4. Reliability and Transparency

The station labels invalid data as unknown and does not present stale measurements as current.

The model rejects inputs that do not meet its requirements. Forecasts run in shadow mode and do not control the environmental alert system.

The Flask dashboard explains measurement status and distinguishes sensor observations from experimental predictions.

These choices help reduce misleading outputs, but they do not guarantee that every possible failure has been tested.

## 5. Limitations

The model was trained on data from a single Sense HAT device during a limited collection period.

Temperature measurements may be affected by heat generated by the Raspberry Pi.

The inference benchmarks measure model execution rather than end-to-end latency or electrical energy consumption.

Accessibility checks were carried out manually, but they do not establish full accessibility conformance.

The prototype is not certified for weather forecasting, health monitoring or safety-critical decisions.

## 6. Conditions Before Deployment

Before this system could be used beyond the classroom, I would require encrypted and authenticated network communication, clearer access controls and stronger protection for stored data.

I would also need independent sensor calibration, testing across different conditions, documented retention and deletion procedures, and further usability and accessibility evaluation.

## 7. Reflection

One benefit of the system is that it processes environmental data locally and can continue collecting readings when network communication is unavailable.

An important trade-off is that simple local deployment improves independence from cloud services but does not automatically solve privacy, security or reliability problems.

A concern that remains unresolved is whether the sensor measurements and model predictions would remain reliable in different physical environments.

This project showed me that responsible edge AI requires more than a model with good prediction accuracy. It also depends on transparent design, evidence-based testing, secure data handling and clear limitations.
